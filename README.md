# 30-Day Forward Deployed Engineer Course

## Goal

Become capable of taking an ambiguous customer problem from:

Customer discovery → requirements → architecture → integration → AI solution → deployment → monitoring → customer handoff.

This is a project-first course. The same project evolves for 30 days.

## Final project

### AI Operations Intelligence Platform

A fictional enterprise customer has:

- CRM data
- PostgreSQL data
- Support tickets
- CSV/Excel data
- Internal documents
- Application logs

The customer wants one system where operations users can:

1. View business metrics.
2. Ask questions in natural language.
3. Search internal knowledge.
4. Investigate customer problems.
5. Automatically receive daily insights.
6. Connect customer-specific systems.
7. Monitor system health.

## Course philosophy

30% study / 70% build.

Do not treat the repository as a set of tutorials to read. Every day has a concrete deliverable.

## Technology stack

| Area | Technology |
|---|---|
| Primary backend language | Python |
| API | FastAPI |
| Database | PostgreSQL |
| Vector search | pgvector |
| Frontend | Angular |
| AI | OpenAI API or equivalent LLM API |
| Containers | Docker |
| Cloud | AWS |
| CI/CD | GitHub Actions |
| Testing | pytest + API/integration tests |
| Monitoring | CloudWatch + application logs |
| Version control | Git/GitHub |

## 30-day roadmap

### Week 1
FDE foundations, customer discovery, APIs, Python, FastAPI, PostgreSQL, integration.

### Week 2
Docker, AWS, deployment, CI/CD, LLM fundamentals, prompting, RAG.

### Week 3
Documents, tool calling, agents, investigation workflows, automation, multi-tenant configuration, security.

### Week 4
Angular dashboard, AI assistant UI, production quality, observability, performance, testing, customer handoff, final FDE simulation.

## Final outcome

At the end, you should be able to explain:

> Give me a customer's messy technical problem and I can understand the workflow, identify the real problem, design the solution, integrate their systems, build the product, deploy it, debug it, evaluate it and explain the business impact.

## Important

The repository intentionally contains assignments and starter material rather than a completed final implementation. You are expected to build the solution yourself.
